# flystem-spring-crud-api

公共契约与运行期支撑类型（ADR 0012：Java 17 字节码，仅引用 Boot 3/4 两代最低公共 API）。
包根 `com.flystem.crud.api`，分 `annotation` / `enums` / `tenant` / `factory` / `page` / `meta` / `wrap` / `io` / `task` / `autoconfigure` 十个子包：

- `annotation.Domain` — 本库自有实体注解，纯 MyBatis 路径识别（ADR 0001 / 0011）；亦可标注于任意路径的实体，携带实体级生成配置（ADR 0009）
- `annotation.DtoViews` — 实体字段 / getter 上配置该字段进入哪几类 DTO（`item` / `detail` / `adminItem` / `adminDetail`）；**方法优先于字段**；未标时普通字段四类皆入、租户字段仅管理面；主键始终进入全部四类
- `annotation.Link` — 外键字段 / getter 上声明关联目标（须实现 `link.Linkable`）；读侧经 `R.relationships` 暴露 id/label（ADR 0024）
- `annotation.GuestControllerGeneration` — 第三方 Guest 面（opt-in）：仅实现 `UUIDGuestId` / `StringGuestId` / `LongGuestId` 的实体生成；与租户面同数据边界；`Guest*` + `getGuestService*`（ADR 0025）
- `guest.GuestId`（sealed）/ `UUIDGuestId` / `StringGuestId` / `LongGuestId` — Guest 面 marker；须 `getGuestId()` 与约定字段 `guestId`（同 `TenantId`）
- `annotation.CrudGeneration` — package-info 生成配置注解（ADR 0009 / 0016），包级默认，可被实体级 `@Domain` 配置逐项覆盖（递归进入层配置内部属性）：包级独有 `scanPackage` / `includes` / `excludes` 圈定参与生成的实体、包级独有 `tenantIdType` 声明全局租户值类型（不可按实体覆盖，与各实体 marker 蕴含类型冲突即生成报错）、包级独有 `principalClass` 声明端点与 Service 方法的用户主体类型（默认 Spring Security `UserDetails`，ADR 0018——**其默认值使任何编译 package-info.java 的项目都需能解析 spring-security-core**）（参与集 = 包扫描集（本包及子孙包，可关）∪ includes − excludes；更近的已配置子包之下的实体由该子包认领），跨层全局项（生成范围、实体根包、产物包布局、命名前缀，从粗到细）为直接属性，各产物层独立配置——`@ControllerGeneration` / `@FormGeneration` / `@McpGeneration` / `@AdminControllerGeneration` / `@ServiceGeneration` / `@ServiceImplGeneration` / `@DataAccessGeneration` / `@DtoGeneration` / `@MapStructGeneration` / `@SpringAutoConfigurationGeneration`（裁剪开关 + api/impl 归属；ServiceFactory 归并于 Service 接口层，随其生成与归属；MCP 工具暴露为与 Controller 同级的独立层，Controller 层端点路径前缀 `pathPrefix`（默认空 = 不加前缀，与管理端同机制、不同面）、免用户主体的操作集 `userlessOperations`（默认空 = 全部端点带用户参数；仅单租户实体可配，多租户实体配了即生成报错，ADR 0018），管理端 Controller（管理面端点，默认覆盖单租户与多租户实体 `includeSingleTenant`、暴露操作集 `operations` 默认全部、仅管理端操作 `adminOnlyOperations`（列出后租户面不暴露、不限租户形态）、路径前缀 `pathPrefix` 默认 `/admin`、安全子配置复用 `@ControllerSecurity`），与 Controller 层嵌套的 `@ControllerSecurity` 子配置（端点安全注解：载体可覆盖（默认 `@PreAuthorize`）+ 表达式模板 + 操作粒度 `securedOperations` + 单租户写侧管理员就地保护 `adminOnlyWrites` / `adminExpression`）均默认关 opt-in）——嵌套为属性；配套 `GenerationMode`（api/impl 生成范围）、`PackageLayout`（产物包布局：`LAYERED` 按产物层分子包，默认 / `FLAT` 同实体产物同包；与实体根包正交）、`TenantIdType`（全局租户值类型：UUID 默认 / STRING / LONG）与 `CrudOperation`（CRUD 操作词汇表；安全粒度、`{action}` 渲染、MCP 子集共用）——**这四个枚举都在 `enums` 子包**，不在 `annotation`（它们是注解属性的取值域、自身不是注解，见下）
- `tenant.TenantId<T>` — 多租户标记接口（sealed 根，包私有），泛型参数声明租户值类型（UUID / String / Long，ADR 0010 / 0005）；**只读**契约，仅 `getTenantId()`，不设 `setTenantId`（产物按实体具体类型填充租户值，ADR 0013）
- `tenant.DefaultTenantIdProvider<T>` sealed 根 + `DefaultUUIDTenantIdProvider` / `DefaultStringTenantIdProvider` / `DefaultLongTenantIdProvider` 公开 marker，默认实现 `DefaultUUIDTenantIdProviderImpl` / `DefaultStringTenantIdProviderImpl` / `DefaultLongTenantIdProviderImpl` — 默认租户哨兵值（零 UUID / 空字符串 / 零 Long，ADR 0005）
- `tenant.TenantIdExtractor`（SPI）/ `tenant.ReflectiveTenantIdExtractor`（默认实现）/ `tenant.TenantIdNotResolvableException` — 当前租户解析（运行期支撑，ADR 0017）：**注入点是生成的多租户 `P{E}ServiceFactoryImpl`**（不是控制器）；端点第一个参数是用户主体（`@AuthenticationPrincipal` 注入，类型由 `@CrudGeneration.principalClass` 配置、默认 `UserDetails`，ADR 0018），端点调 `serviceFactory.getService(user)`，由工厂经 `extract(user, UUID.class)` 从该主体取租户值后返回租户绑定的 Service。接口唯一抽象方法为 `extract(UserDetails, Class)`；默认实现识别两种主体形态（实现租户 marker，或有 public `getTenantId()`）。解析不出抛 `TenantIdNotResolvableException`，**不回落**默认租户（ADR 0005）
- `wrap.R<T>` — 默认的统一结果封装：`code` / `message` / `data` / `relationships`（+ 派生 `success`），不可变、仅 getter，Jackson 可直接序列化。静态工厂 `ok(data)` / `ok(data, relationships)` / `fail(code, message)`。由 `ResultWrapper#wrap` 产出；本类本身**不是**合法的 `resultWrapper` 配置值
- `wrap.ResultWrapper`（SPI）/ `wrap.DefaultResultWrapper`（默认实现）— 结果包装（ADR 0020 / 0024）：`wrap` 后经 `link.RelationshipLoader` 按类型批量填充 `R.relationships`；刻意不吞异常；自定义 bean 整体替换
- `link.Linkable` / `LinkView` / `HasRelations` / `RelationRef` / `RelationshipLoader` / `TypedLinkableLoader` / `DefaultRelationshipLoader` — 读侧关联（ADR 0024）：目标实现 Linkable；DTO 实现 HasRelations；关系写入 R.relationships（仅 id/label）
- `io.ImportParser` / `io.ExportWriter`（SPI）+ `io.ExportFile`（载体）+ `io.JsonImportParser` / `io.JsonExportWriter`（默认实现）— IMPORT / EXPORT 的文件编解码（ADR 0021）：IMPORT 端点收 `MultipartFile`、**在请求线程内**经 `ImportParser` 得 `List<DTO>`（multipart 临时文件在请求结束后即被清理，异步线程再去读已拿不到，ADR 0022）；EXPORT 在**异步任务体**里经 `ExportWriter` 得 `ExportFile`（文件名 + Content-Type + 字节）交任务管理器保管，客户端再经下载端点作为**附件**取回（见 `task` 子包）。`ExportFile` 也可由 IMPORT 任务体经 `TaskContext.resultFile` 交出（如驳回 / 校验明细）——下载端点不区分操作类型。默认 **JSON**（零额外依赖：控制器层本就要求 spring-web，Boot web 应用恒有 Jackson；故 `-api` 对 jackson-databind 也是 `compileOnly`），换 CSV / Excel 即声明自己的 bean 整体替换。`ExportFile` **不含任何 HTTP 类型**（那是控制器层的事），故 `-api` 不依赖 spring-web、编解码也能在非 Web 场景复用。默认解析器**校验扩展名**：非 `.json` 直接抛 `IOException` 并说明出路，而不是让 Jackson 吐 `Unrecognized token 'PK'`
- `task.CrudTaskManager`（SPI）/ `task.InMemoryCrudTaskManager`（默认实现）/ `task.CrudTask`（快照）/ `task.TaskStatus` / `task.TaskBody`（任务体）/ `task.TaskContext`（进度打点）/ `task.TaskNotFoundException` — **异步导入 / 导出任务**（ADR 0022）：生成的 IMPORT / EXPORT 端点**不同步干活**，`submit(entity, operation, scope, body)` 后立即返回 `CrudTask`（id / `TaskStatus` / 进度百分比 / 条数 / 结果文件名与 Content-Type / 提交与结束时刻）。时间戳是 **ISO-8601 字符串**（UTC）而非 `Instant`——本子包**纯 JDK**，不引 jackson-jsr310、不引 Spring 与 Security 任何类型，故非 Web 场景（定时任务、消息消费）同样可用。客户端轮询 `find(taskId, scope)`、或经 `page(entity, scope, TaskPageQuery)` 分页查询本实体可见任务（过滤 + `page`，`PageResult<CrudTask>`，按 `submittedAt` 倒序；无命中为空页），成功后 `download(taskId, scope)` 取 `io.ExportFile`（端点映射为 `ResponseEntity<Resource>`）。**`scope` 是可见性边界、永不为 null/blank**：提交时记下（生成产物给的是工厂的 `taskScope(user)`，粒度由 `@ServiceGeneration.taskScope` 决定——默认 `USER` = `getUsername()`，可改为 `TENANT` = 租户值字符串），查询 / 列表 / 下载须给出**相同**值；单条查询 / 下载**不匹配与不存在同样返回 `null`**——不给跨边界探测留「这个 id 存在吗」的 oracle（导出文件就是数据本身）；列表另按 `entity` 收窄（SPI 全应用共享，否则 Book 会列出 Account 任务）。`TaskStatus` 只有 `PENDING` / `RUNNING` / `SUCCEEDED` / `FAILED`，刻意无 `CANCELLED`。默认实现是**进程内**的：自建守护线程池（2 线程 / 有界队列 100，满则 `submit` 抛 `IllegalStateException` 而**不**静默降级为同步）+ `ConcurrentHashMap` 存状态 + 结果文件在堆里 + 30 分钟 TTL，故**不持久、不跨实例、大表导出吃堆**——生产须声明自己的持久化实现 bean 整体替换（数据库 / Redis / 对象存储 + 持久队列）
- `autoconfigure.FlystemSpringCrudAutoConfiguration` — 库级 Spring Boot 自动配置（**区别于**每实体一份的生成产物 `F<Entity>AutoConfiguration`）：使用方未声明 `TenantIdExtractor` / `ResultWrapper` / `ImportParser` / `ExportWriter` / `CrudTaskManager` bean 时注册各自默认实现（均 `@ConditionalOnMissingBean`），声明自己的 bean 即整体替换。文件编解码那块以 `@ConditionalOnClass(ObjectMapper.class)` 守卫，并用 `ObjectProvider` 优先复用**应用自己的** `ObjectMapper`（沿用其日期格式、命名策略等配置）；`CrudTaskManager` 的默认实现 `InMemoryCrudTaskManager` 与 `ResultWrapper` 一样**只用 JDK 类型、挂在顶层无 `@ConditionalOnClass` 守卫**（ADR 0022）。经 `META-INF/spring/org.springframework.boot.autoconfigure.AutoConfiguration.imports` 注册（Boot 3 / 4 同机制）；以 `@ConditionalOnClass(UserDetails)` 守卫并置于嵌套配置类，未引 spring-security-core 的项目不会被加载。**本模块引用第三方类型之处**（Spring Security 的 `Authentication` / `UserDetails`、Boot 的 `@AutoConfiguration` / `@ConditionalOn*`，均 `compileOnly` 不传递）——仅多租户 Controller 产物需要，使用方自引 `spring-security-core`（ADR 0008 opt-in，同 `@ControllerSecurity`）；非 Boot 的纯 Spring 使用方需自行声明 bean
- `factory.ServiceFactory<S>` / `factory.TenantServiceFactory<S, T>` — 每实体生成工厂的基础类型：单租户仅无参 `getService()`，多租户另有 `getService(tenantId)`（ADR 0004）。生成的每实体接口在此之上**再声明一个 `getService(principalClass)`**：多租户实现经 `TenantIdExtractor` 从用户主体解析租户后委派 `getService(tenantId)`，单租户实现等价于无参入口。该方法**不放在这两个基类型上**——基类型里 `getService(T)` 与 `getService(U)` 擦除后同为 `getService(Object)`，会 name clash；生成侧两者都是具体类型才是合法重载
- `enums.*` — 配置注解属性的取值域枚举，与 `annotation` 子包分立（它们自身不是注解；留在 `annotation` 下会让「这个包里都是注解」的直觉失效、也让按包名筛注解的工具误收）：`CrudOperation`（CRUD 操作词汇表：CREATE / GET / LIST / UPDATE / DELETE / IMPORT / EXPORT / COUNT / PAGE / EXISTS / META（META 产出 `meta.QueryMeta` 实体查询元信息，端点 `GET /{e}/meta`）；被 `@ControllerSecurity.securedOperations`、`@ControllerGeneration.userlessOperations`、`@AdminControllerGeneration.operations` / `adminOnlyOperations` 引用，impl 侧 Service 方法集与端点集与之对齐，协议 §4.1）、`GenerationMode`（api / impl 生成范围）、`PackageLayout`（产物包布局 LAYERED / FLAT）、`TenantIdType`（全局租户值类型 UUID / STRING / LONG）、`TaskScope`（异步任务可见性粒度 USER 默认 / TENANT，`@ServiceGeneration.taskScope`）。**新增枚举的判据**见该包 `package-info`：只收纯取值类型，承载行为或运行期逻辑的（`page.PageResult`、`tenant.TenantIdExtractor`）仍按领域放对应子包
- `page.PageResult<T>` — 中立分页结果（ADR 0019）：不可变值对象，承载「一页数据 + 分页元数据」（`items` / `currentPage` / `pageSize` / `total`，派生 `pages`；页内元素叫 `items` 而非 MyBatis-Plus 味的 `records`），不绑定任何持久层或 Web 框架的分页类型。字段名与入参侧 `PageParam` **对齐**，故同一次分页往返的请求体与响应体用同一套词汇（原为 MyBatis-Plus 风格的 `current` / `size`，已改，见 ADR 0019 演进段）。分页产物（转换层的 `toDtoPage`、Service 的 `page` 方法与 Controller 的 `/page` 端点）以它出入，故对外契约不泄漏 MyBatis-Plus 的 `IPage` 或 Spring Data 的 `Page`。页码**从 1 开始**（与 MyBatis-Plus 一致；Spring Data 的 `getNumber()` 需 `+1`，构造时 `currentPage < 1` 即抛 `IllegalArgumentException`），`pageSize <= 0` 表示未分页（此时 `getPages()` 为 0）。仅 getter、私有构造 + 静态工厂 `of` / `empty`，Jackson 可直接序列化为响应体；**无第三方依赖**——各栈的适配留在产物模板内，`-api` 不引 mybatis-plus / spring-data
- `page.PageParam` — 分页**入参**（与出参 `PageResult` 成对）：把「第几页 / 每页多少条」合成一个可嵌套字段，供生成的 `{P}{E}PageQuery` 以单个属性持有，于是请求体是 `{"page":{"currentPage":2,"pageSize":20}}`。页码**从 1 开始**（与 `PageResult` 同基准）。**`<= 0` 一律视为「未指定」**而非合法值：`currentPage` 回落 1（否则 `PageResult` 构造期抛错、端点 500），`pageSize` 经无参 `resolvePageSize()` 回落库级 `DEFAULT_PAGE_SIZE`（否则 MyBatis-Plus 把 `size < 0` 当作「不分页、取全量」，客户端用一个 `-1` 就能拉走整表）。`hasPageSize()` 区分「未指定」与「显式正值」——生成的查询条件类据此在未指定时改用实体级 `@ControllerGeneration.defaultPageSize`，否则 Jackson 新建 `PageParam` 时部分载荷会让该配置静默失效。**可变**（无参构造 + setter），与不可变的 `PageResult` 刻意不同：本类是反序列化目标
- `meta.QueryMeta` / `meta.QueryFieldMeta` / `meta.QueryRelationMeta` — 实体查询元信息（`CrudOperation.META` 的返回类型）：实体资源名（恒小写）+ 可查询字段说明（字段名 / Java 类型简名 / 数据库列名 / 是否租户字段）+ `@Link` 关联说明（关系名 / 外键字段 / 目标类型简名 / 级联路径）。生成侧另产 `{P}{E}Meta` 常量类（`ENTITY` + `get()`），`Service#meta()` / 异步任务 entity / 导出文件名主干 / 端点 `@RequestMapping` 路径段同源。由生成期已知的实体元数据直接构造（不查库）。租户字段标 `tenantField=true`——它由租户边界自动约束（ADR 0013），不应作为用户可填条件暴露。「含义 / 显示名」与「可用操作符」待查询条件的字段落地后补（wb#6）

使用方的编译依赖仅此一个模块（ADR 0008）。端点是否用统一结果类包装，由 `@ControllerGeneration.resultWrapper` 配置（默认 `Void.class` = **不包装**；非 Void 须实现 `ResultWrapper` SPI，ADR 0020）。IMPORT / EXPORT 则**恒为异步任务**（不可配，ADR 0022），故运行期总需要一个 `task.CrudTaskManager` bean——Boot 项目由本模块的自动配置给默认的内存实现，非 Boot 的纯 Spring 项目须自行声明（同 `ImportParser` / `ExportWriter` 的约定）。注意与"api 产物"（生成结果的接口侧）区分，见 `CONTEXT.md`。
